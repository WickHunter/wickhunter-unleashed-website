TV Signal

Open and manage deals from your TradingView alerts.

Connect TradingView to TV Signal | Wick Hunter Course 55:47 · Watch on YouTube ↗TV Signal: Every Setting and Command Explained | Wick Hunter12:15 · Watch on YouTube ↗

Your TradingView alert decides when. The bot decides size, DCA and exit, using the same deal engine as the other bots. It does not second-guess the signal: if the alert arrives and the guards pass (direction, pairs, caps, blacklists), it trades. You can run up to ten TV Signal bots, each with its own address and secret.

What you need

  • A paid TradingView plan (webhooks are not on the free tier).
  • A public HTTPS address for your server on a standard port, with a trusted certificate. Local and home-network addresses cannot be reached by TradingView.

Set it up

  1. Select the account and market in the header. The bot trades there for life.
  2. Create Bot → TV Signal, set direction, pairs, size, ladder and exits, then Save & enable.
  3. Copy the Webhook URL and the message template from the webhook panel. The template already contains your secret.
  4. In TradingView, create the alert on the chart of the pair you trade. Use Once Per Bar Close.
  5. Tick Webhook URL, paste the address, and paste the template as the whole message (no extra text).
  6. Fire one test alert and check Recent signals on the bot's form: a green tick means accepted, a red cross shows the refusal reason.

TradingView reporting "delivered" only confirms the app received the alert, not that a trade opened. Always check Recent signals.

Recommended starter configuration

A suggestion, not a default: Direction to match your strategy, Max longs/shorts 1, Pairs Allowlist with only the symbols your alerts use, a small Dollar base order, 3–5× leverage, DCA orders 0, Fixed % take profit, stop loss on.

Duplicate cooldown and minimum time between entries

  • Duplicate cooldown (seconds) ignores the same open alert for the same pair repeated within that time. TradingView sometimes delivers an alert twice; this absorbs it.
  • Minimum time between new entries (seconds, blank or 0 = off) is a separate, bot-wide wait: after the bot opens a deal, every open alert, on any pair, is refused with "Entry cooldown: next entry allowed in Xm Ys." until the time has passed. Closes, DCAs and TP/SL changes still work. An alert that did not open a deal does not start the wait, and the wait carries over a restart.

The {{ticker}} trap

{{ticker}} resolves to the chart the alert was created on, forever. An alert built on a BTC chart keeps sending BTCUSDT. Write the symbol literally, for example "symbol":"SOLUSDT", unless you deliberately build one alert per chart.

Keep the secret private

Anyone with the address and secret can make this bot trade. Redact it like an API key. If it leaks, rotate it first (type ROTATE to confirm), then paste the new template into each alert by hand; old alerts stop working immediately.

Common mistakes

  • Once Per Bar instead of Once Per Bar Close: fires on candles that can still reverse.
  • Extra text, smart quotes or a message copied from a different bot: refused as unauthorised.
  • Any pair mode with a typo'd symbol: opens a deal on a coin you never chose.
  • A paused bot refuses signals; they are not replayed later.
  • A "size" in the message overrides the form's base order for that deal.
